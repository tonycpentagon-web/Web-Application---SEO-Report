# SEO Team Lead evaluation

Create your own Super Admin using local/New-TestAdmin.ps1; no default accounts/passwords are shipped. Log in and create an SEO Admin, SEO Manager, two SEO Executives and a Client Viewer through Team Management, using your own test emails. Account invitation/reset tokens are private: local log mail writes them to backend/storage/logs/laravel.log rather than sending email. Use only your own test invitation and never share or package logs. Individual roles and project assignments must be configured explicitly.

Evaluation checklist:

- Create a clearly named Synthetic Evaluation client, website and project. Assign an executive and manager.
- Create August 2026 and upload the six labelled synthetic PDFs in backend/tests/fixtures/monthly/ beginning 08-. Generate SEO Report and inspect all sections, keyword/activity rows, AI screenshots and events. Draft/provisional data must remain labelled and source-backed.
- Create September 2026 using the six 09- PDFs. Confirm August sources, values and history remain unchanged. Compare only compatible complete dates/metric definitions.
- Create a second synthetic project and October 2026. Upload local/fixtures mixed scanned PDF, PNG/JPG, Excel and CSV. Inspect actual OCR and classification warnings: missing sections/ambiguous metrics do not become approved invented values. Partial inputs need additional real source-supported sections before publication is eligible.
- Export the complete Draft PDF; inspect tables, images, watermarks and page breaks. Use Advanced Review to inspect evidence, verify required records, resolve material warnings with an explanation and explicitly approve source-supported commentary.
- Submit for manager review. As manager review, approve and publish only an eligible SYNTHETIC report. An incomplete report must stay blocked. Export a published PDF.
- In Share Report choose the default account link for a Client Viewer and verify authorized month history. Then for a synthetic publication only choose Anyone with the link, tick explicit consent and create a bounded-expiry link. Open that link in a private browser with no login; verify only that publication is available and PDF respects Allow Download.
- Archive/restore a test report. Move September to Trash, verify its links fail immediately and August is intact. Restore it and verify old access stays revoked. Create a new link deliberately if needed. Restore a trashed month instead of duplicating the same month. A permanently deleted month can be recreated after configured retention.
- Replace a wrong Draft source; verify the original moves to Trash only after the new upload succeeds, and regenerate/verify before publishing. Active processing blocks removal/reset. Published source changes require the existing archive ? restore-to-Draft revision workflow; immutable old snapshot bytes are never edited in place.
- Use Reset Generated Report Data on a Draft. Inspect exact counts, confirm, regenerate and verify no duplicated observations. Original uploads and other months remain intact. Historical commentary and approvals remain audit evidence; their validity is revoked by source/revision changes rather than erased.
- In Trash verify clients, projects, reports and recoverable documents, parent-first restore, role restrictions and the configured retention period. Permanent removal requires typed DELETE plus ID. SEO Admin can purge permitted reports/documents; parent clients/projects require Super Admin. A source referenced by retained evidence cannot be purged independently: keep it in Trash or purge its owning report after retention. Never reduce retention to delete real client data.
- Verify another employee cannot read another client's reports, a client cannot access source/admin routes and concurrent stale edits are rejected. Do not approve or delete real Hann's data as part of evaluation.

No real client publication or destructive operation is automatic. Archive/Trash hide data; permanent removal is explicit and audited. TRASH_RETENTION_DAYS defaults to 30 (minimum 1). There is no automatic purge of Trash records. Required decision/access audit is retained indefinitely in retained_lifecycle_events pending a separately defined legal retention policy. Authorized purges queue private-file removal; the scheduler processes that queue once per minute and retries failures. Monitor System Health/logs if it stops.
