# Backup and recovery

Protect MySQL data, private uploads/evidence/PDF snapshots, application key/environment, and the matching source/lockfile release together. Store encrypted copies off-host with restricted backup-only credentials; restore credentials and APP_KEY recovery must be tested independently. Encrypting transport alone is insufficient. Never place SQL, private files or environment backups in Git or a web root.

ops/backup-production.sh is a reviewable Linux template, not an installed schedule. It requires restic, a pre-initialized encrypted repository, a private password file, a restricted MySQL defaults file and explicit absolute paths. It puts the application in maintenance, stops both worker groups, streams a consistent mysqldump into encrypted restic, then backs up private storage and .env with the same set tag and checks repository integrity. Schedule during an approved window. Confirm both database and files snapshots exist with the same set tag; an interrupted set is incomplete. The trap attempts to resume workers and application: independently confirm availability after success or failure. Do not execute it against this Windows workspace.

Suggested policy for operator approval: nightly backups, 30 daily/12 monthly points, separate immutable/offsite copies, alerts for failure and capacity. Retention deletion is deliberately not automatic. Define measured RPO/RTO with the business; no timing guarantee has been established here. Keep backup logs free of credentials and report content.

Recovery drill: provision an isolated empty database and private directory with separate credentials/network. Select a complete matching snapshot pair, restore only there, verify hashes, import SQL, run integrity/foreign-key/count checks and inspect originals/evidence/private PDFs under a test-only app. Verify source checksums, role isolation, Draft status and publication/share restrictions. Disable mail, public access, schedules and production queue consumers. Never point a recovery drill at the active database or uploads. Record recovery duration and operator evidence before allowing production cutover.

Local evidence: ops/backup_drill.py creates a disposable three-client synthetic SQLite store, archives hashed synthetic originals/PDFs, restores into a new empty directory, checks integrity/counts/checksums and rejects traversal/nonempty destinations. This proves that drill's controls only; it does not prove encrypted restic, MySQL restore or offsite availability. The preserved local SQLite baseline is additionally checked using a separate read-only restored copy. Production recovery remains an explicit release gate.
